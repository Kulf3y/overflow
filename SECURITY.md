# Security Policy

Overflow is being designed with security-first principles.

## Core security rules

- Fail closed when a critical policy cannot be guaranteed.
- Do not log raw prompts by default.
- Do not store secrets in plain text.
- Use provider allowlists.
- Use least-privilege tokens and credentials.
- Keep audit records tamper-evident where possible.
- Prefer self-hosted or EU-controlled routes for sensitive workloads.

## Current status

Overflow is in early development. Security features are being added step by step.

## Reporting a vulnerability

Do not open a public GitHub issue for security problems.

If you find a security issue, report it privately to the maintainers.
